# Documentation

The entry point to this repository's documentation: what each document is for, who it is for,
and whether it describes the repository as it is now or records a stage as it was. Every
Markdown document under `docs/` has exactly one entry in the tables below, and
`python -m scripts.doc_links` fails if one is not reachable from this page, or if any relative
link or anchor in `docs/`, the root [README](../README.md) or the
[database README](../database/README.md) does not resolve.

The root [README](../README.md) is the project overview: what the platform is, how to run it,
and its [known limitations](../README.md#known-limitations). This page does not repeat it.

**About the data.** The demo stack's hotels, guests and bookings are synthetic, generated by
`scripts/seed_demo.py`. The offline demand model's training data, its source and its licence are
described in [ml-training-data.md](ml-training-data.md); what that data can and cannot support is
in the [model card](ml-model-card.md).

## Status of a document

Each entry below carries one of three statuses.

- **Current** — maintained: it describes the repository as it is, and tests hold parts of it to
  the code. Where it records the stage that introduced something, later changes are added to it.
- **Frozen record** — the record of a stage, a measurement or a decision, kept as written. It is
  accurate about what it records; later work is recorded elsewhere, not by editing it. Some are
  bound by checksum (see [below](#frozen-and-checksum-bound-records)).
- **Redirect** — a path kept because code comments, stage records or links cite it. The stage
  snapshot that lived there was consolidated into a current document on 2026-11-25 (roadmap
  R6.1); the page is a short map from each of its old sections to where that section is now,
  and names the commit at which the snapshot as last written can still be read. There is no
  longer any superseded snapshot.

Stage-dated figures (a migration head, an operation count, a number of tools) in a frozen record
are correct for that stage. The current figures are in the root
[README](../README.md), where `tests/backend/test_readme_counts.py` computes each one from the
code.

## Frozen and checksum-bound records

Some text is bound by content, not only by convention. Editing it fails a test, by design.

- **§3.5 of [retrieval-evaluation-decision.md](retrieval-evaluation-decision.md#35-relevance-grades)**,
  the relevance rubric the reviewer signed off: its SHA-256 is recorded in the sign-off
  (`tests/evaluation/datasets/knowledge_retrieval_v2.signoff.json`) and checked by
  `tests/evaluation/test_retrieval_signoff.py`. The record's path is a constant in a
  fingerprinted module, so the file cannot move either.
- **The review sheet and form** the reviewer worked from,
  `tests/evaluation/datasets/knowledge_retrieval_v2.review.md` and `.review.json`: the sheet's
  SHA-256 is checked by `tests/evaluation/test_retrieval_review.py`, and the form's is bound
  into the sign-off and checked by `tests/evaluation/test_retrieval_signoff.py`.
- **The pinned retrieval report**, `tests/evaluation/retrieval_report_v2.json`, changes only by
  the re-pin process of [§12.6](retrieval-evaluation-decision.md#126-source-hashing-ci-artifacts-and-the-baseline).

Other records are held by tests to particular statements rather than to every byte. Those tests
open the documents by path, so the documents above stay where they are.
